# Шаг 9. OSINT-слой: поиск, материал, сюжет

Шаг закрывает этапы 1–2 из `docs/news-osint.md`: полнотекстовый поиск по архиву с фильтрами, страница материала с историей правок и страница сюжета. Диффы правок, сущности, граф связей и всплески остаются на следующие шаги.

Ограничения площадки: одно ядро, 500 МБ памяти, без JavaScript. Тяжёлые выборки — только по запросу и с потолком строк [CORE-025]. Наблюдение и машинная оценка разделены [NEWS-008]. В каждой строке выдачи — ссылка на оригинал [NEWS-007]. Отсутствие данных не равно нулю [NEWS-001].

## 1. Поисковый индекс

Виртуальная таблица FTS5 поверх `items` во внешнем содержимом, чтобы не дублировать тексты:

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS items_fts USING fts5(
  title, lead, body,
  content='items', content_rowid='id',
  tokenize="unicode61 remove_diacritics 2"
);

CREATE TRIGGER IF NOT EXISTS items_ai AFTER INSERT ON items BEGIN
  INSERT INTO items_fts(rowid, title, lead, body)
  VALUES (new.id, new.title, new.lead, new.body);
END;

CREATE TRIGGER IF NOT EXISTS items_ad AFTER DELETE ON items BEGIN
  INSERT INTO items_fts(items_fts, rowid, title, lead, body)
  VALUES ('delete', old.id, old.title, old.lead, old.body);
END;

CREATE TRIGGER IF NOT EXISTS items_au AFTER UPDATE ON items BEGIN
  INSERT INTO items_fts(items_fts, rowid, title, lead, body)
  VALUES ('delete', old.id, old.title, old.lead, old.body);
  INSERT INTO items_fts(rowid, title, lead, body)
  VALUES (new.id, new.title, new.lead, new.body);
END;
```

Первичное заполнение существующей базы — один раз при миграции:

```sql
INSERT INTO items_fts(items_fts) VALUES('rebuild');
```

Создание таблицы и триггеров идёт в ту же функцию инициализации схемы, что и `LATE_COLUMNS`: при запуске проверяем наличие `items_fts` в `sqlite_master` и при отсутствии создаём и перестраиваем.

Запас по памяти: индекс примерно равен 60–80 % объёма текстов, ориентир из `docs/news-osint.md` — около 3 МБ в день. Раз в сутки в обслуживании вызываем `INSERT INTO items_fts(items_fts) VALUES('optimize');`.

## 2. API хранилища

В `news/store.py`:

```python
def найти(
    запрос: str,
    *,
    источник: str | None = None,
    с_даты: str | None = None,
    по_дату: str | None = None,
    тема: str | None = None,
    только_оригиналы: bool = False,
    только_с_правками: bool = False,
    лимит: int = 50,
    сдвиг: int = 0,
) -> list[dict]
```

- Запрос уходит в `items_fts MATCH ?`, ранжирование `ORDER BY bm25(items_fts, 4.0, 2.0, 1.0), published_at DESC` — заголовок весит больше тела.
- `только_оригиналы` — `dup_of IS NULL`; `только_с_правками` — `EXISTS (SELECT 1 FROM item_revisions r WHERE r.item_id = items.id)`.
- Даты сравниваем через `date(published_at)`, формат ISO.
- Лимит жёстко ограничен сверху (200), сдвиг постраничный.
- Пользовательский ввод экранируем: спецсимволы FTS5 (`"`, `*`, `-`, `:`) вырезаем или оборачиваем фразу в кавычки, чтобы не падать на синтаксисе.

Дополнительно:

```python
def материал(ид: int) -> dict | None      # материал + список ревизий
def сюжет(ид: int) -> dict | None         # участники сюжета по времени
```

Для сюжета считаем: кто опубликовал первым, лид-тайм каждого последующего издания относительно первого, кто попал в сюжет как повтор (`dup_of`).

## 3. Маршруты

В `news/web.py` и функции разметки в `news/pages.py` (чистые функции, `html.escape` на всём пользовательском):

| Маршрут | Назначение |
| --- | --- |
| `GET /поиск` | форма и выдача: `?q=`, `?источник=`, `?с=`, `?по=`, `?тема=`, `?оригиналы=1`, `?правки=1`, `?стр=` |
| `GET /материал?id=` | материал: заголовок, лид, источник, время публикации и обнаружения, ссылка на оригинал, история ревизий, сюжет |
| `GET /сюжет?id=` | сюжет: кто первым, лид-тайм остальных, список публикаций по времени |

Правила выдачи: в каждой строке — издание, время публикации и ссылка на оригинал; пустой результат — явная надпись «ничего не найдено», а не пустая таблица; постраничность по 50 строк, кнопки «дальше»/«назад» обычными ссылками.

Страница материала показывает историю правок как перечень «когда — новый заголовок — длина»: текстов ревизий мы пока не храним, диффы откладываем на следующий шаг и отмечаем это на странице.

## 4. Тесты

В `tests/test_news_search.py` и `tests/test_news_web.py`:

- индекс строится на пустой и на заполненной базе (`rebuild` не ломает существующие данные);
- триггеры: вставка, изменение и удаление материала меняют выдачу поиска;
- фильтры: источник, диапазон дат, тема, только оригиналы, только с правками;
- ранжирование: совпадение в заголовке выше совпадения в теле;
- экранирование: запрос с кавычками и звёздочкой не роняет поиск;
- лимит и сдвиг: потолок строк соблюдается;
- страницы `/поиск`, `/материал`, `/сюжет` отвечают 200, содержат ссылку на оригинал и экранируют HTML в заголовках;
- сюжет: первый источник и лид-тайм считаются верно на подготовленных данных.

## 5. Порядок работ

1. Схема: `items_fts`, триггеры, разовый `rebuild`, `optimize` в обслуживании.
2. `store.найти`, `store.материал`, `store.сюжет` + тесты хранилища.
3. Маршруты и разметка + тесты веба.
4. Замер: размер индекса и время запроса на реальной базе, запись результата в `docs/news-osint.md`.

## 6. Риски

- Рост базы: индекс удваивает вес текстов. Решение — `optimize` и обсуждаемое хранение текстов год.
- Тяжёлый запрос на одном ядре: спасают лимит строк, постраничность и отсутствие поиска без непустого запроса.
- Морфология: FTS5 ищет по словоформам. Стеммер русского не подключаем, вместо этого разрешаем префиксный поиск по хвосту слова в выдаче формы поиска.
