# Как вести код

Правила с тегами живут в `wiki/rules/`; здесь — короткая выжимка без дублирования формулировок [DOC-002].

- Язык комментариев и документации — русский; имена модулей и функций — английские, единообразно с соседями; русские имена допустимы в ключах словарей, маршрутах и флагах CLI.
- Файл не длиннее **30 КБ** [CORE-024 в редакции `wiki/rules/news.md` от 24.09.2026]. Разрослось — делим с реэкспортом публичных имён и по одному файлу на коммит [CODE-003].
- Зависимости: в рантайме только `httpx`. Новая зависимость — отдельное обсуждение.
- Параметр «на будущее» и умолчание «для отладки» не заводятся [CODE-001]; правка общего механизма заканчивается поиском всех потребителей [CODE-002].
- Деградация называет причину: узкий `except` и запись в лог [ERR-001].
- Каждое изменение сопровождается тестом и правкой документации [DOC-001]; пара «записали → прочитали» проверяется парным тестом [CFG-002].
- Коммит описывает результат, а не процесс.
- Фрагменты старого проекта берём из ветки `legacy` осознанно: переносим только нужное, сразу под правила FPNews и вместе с тестом.
