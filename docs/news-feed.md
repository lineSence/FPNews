# Общая лента, папки и адресная отдача

Три вопроса, на которые раньше ответить было нечем: «что вообще вышло за сутки», «разложи это по смыслу» и «шли мне в бот не всё подряд, а вот эти темы из вот этих изданий».

Ограничения прежние: одно ядро, 500 МБ, без JavaScript, без модели в пути показа страницы [CORE-025], [NEWS-002].

## 1. Что такое «общая лента»

`/новости` («Пришло вам») — журнал отправок: что бот вам прислал. Это не весь выход, а его отобранная часть.

`/лента` («Общая лента») — весь собранный выход, включая то, что не попало ни в одну тему. Разделение намеренное: иначе настройка отдачи незаметно превращается в фильтр наблюдения, и архив начинает врать о том, что выходило [NEWS-001].

## 2. Отбор

Модуль `news/stream.py`, чистые функции над базой:

```python
Filter(words, sources, topic_id, period, since, until, sort, group, only_original, page)
def read(query, many) -> Filter    # из строки запроса, всё непонятное — по умолчанию
def select(conn, flt) -> list[dict]
def folders(conn, rows, flt, user_id) -> list[(папка, строки)]
def link(flt, **changes) -> str    # адрес с изменённым полем
```

- **Слова.** Есть слова — идём через FTS5 (`items_fts`), нет — обычная выборка по `items`. Отдельный путь потому, что «покажи всё за сутки» не должен требовать поискового выражения.
- **Издания.** Несколько сразу: `издание=dp&издание=fontanka`. Обычные галочки, обычный GET, ссылку можно сохранить в закладки и переслать.
- **Время.** Период (`сутки`, `три дня`, `неделя`, `месяц`, `всё время`) или точные даты «с» и «по». Даты сравниваются по времени публикации, а где его нет — по моменту обнаружения: это разные величины, и подменять одну другой нельзя [NEWS-001].
- **Тема.** Слова темы подставляются в выражение поиска, её издания — в фильтр, если человек не выбрал свои.
- **Порядок:** новые сверху, старые сверху, по изданию, по задержке (публикация → наше обнаружение; где времени публикации нет, строка уходит вниз, а не притворяется нулём).
- **Потолки:** 50 строк на страницу, не больше 200 за запрос.

## 3. Папки

«Умная сортировка» здесь означает раскладку по уже сделанным наблюдениям, а не по догадке модели:

- **по теме** — папка на каждую тему человека, слова сверяются тем же правилом, что и в отдаче (`news/topics.py`). Материал попадает в первую подходящую папку, остальное — «Прочее»: иначе одна новость размножилась бы по экрану и сломала счёт.
- **по сюжету** — перепечатки ложатся к оригиналу (`items.dup_of`, склейку делает шаг дедупликации). Материал без перепечаток остаётся папкой из одной строки; прятать его нельзя.
- **по дате** и **по изданию** — механическая группировка, когда нужен обзор, а не смысл.

Сумма строк по папкам всегда равна числу отобранных строк — это проверяется тестом.

## 4. Отдача в Telegram: что и откуда

Страница `/телеграм` теперь состоит из трёх частей.

1. **Виды сообщений и тихие часы** (было): сырое, дополнение, изменение, тоже_написали, запрос.
2. **Издания в отдаче** — `users.sources`, общий список на человека. Пусто значит «все», а не «ни одного»: у старых записей колонки не было, и трактовать её отсутствие как запрет означало бы молча выключить рассылку.
3. **Темы в отдаче** — на каждую тему галочка «отдавать в бот» (`topics.enabled`) и свой набор изданий (`topics.sources`). Выключенная тема перестаёт слать сообщения, но остаётся темой: её слова по-прежнему раскладывают ленту по папкам.

Проверка стоит в `news/deliver.py`: `wants` (вид сообщения) и `allowed` (издание) — перед каждой отправкой, включая перепечатки и находки по сохранённым запросам.

Важное разделение: фильтр отдачи — не фильтр сбора. Выключенное на `/телеграм` издание всё равно собирается, лежит в архиве и видно в общей ленте. Чтобы не опрашивать его вовсе, есть выключатель на `/источники`.
