# Доступ: приглашение из рук в руки

Замысел владельца: никакой саморегистрации. Человек попадает внутрь, только
если владелец выдал ему лично созданный токен. Ниже — как это устроить и
что ломается при выходе в открытый интернет.

## Правило

Доступ — это **две разные вещи**, и путать их нельзя:

1. **Приглашение** — одноразовый токен, который выдаёт владелец. Он говорит
   «этому человеку можно», действует один раз и умирает.
2. **Вход** — то, чем человек пользуется каждый день. Это по-прежнему
   одноразовый код из бота плюс кука сессии.

Приглашение не заменяет вход. Иначе токен становится вечным паролем: он
осядет в переписке, в буфере обмена, в истории команд — и будет работать.

## Что появляется в базе

```
CREATE TABLE invites (
    id         INTEGER PRIMARY KEY,
    отпечаток  TEXT NOT NULL UNIQUE,   -- blake2b от токена, сам токен не храним
    кому       TEXT NOT NULL,          -- подпись владельца: «Марине из Фонтанки»
    роль       TEXT NOT NULL,          -- владелец | читатель
    выдан_в    TEXT NOT NULL,
    годен_до   TEXT NOT NULL,          -- по умолчанию 72 часа
    использован_в TEXT,
    кем_использован INTEGER,           -- users.id, когда приглашение сработало
    отозван_в  TEXT
)
```

И одна колонка в `users`: `роль TEXT NOT NULL DEFAULT 'читатель'`.

Токен не хранится. В базе лежит `blake2b(токен, key=FPNEWS_SECRET)`: утечка
копии базы не даёт войти. Сравнение — через `secrets.compare_digest`.

## Как это выглядит в работе

1. Владелец в боте: `/пригласить Марина читатель`. Бот отвечает строкой
   `fpn_` плюс 32 случайных байта в base64url и напоминает, что она
   показывается один раз.
2. Владелец передаёт её человеку тем способом, который считает безопасным.
3. Человек открывает `https://…/приглашение?код=…`. Сервер: находит
   отпечаток, проверяет срок и что не использовано, **и не пускает сразу** —
   просит назвать себя боту. Человек пишет боту `/вход`, бот присылает
   обычный одноразовый код, и только после него появляется сессия.
4. Приглашение помечается использованным и привязывается к `users.id`.

Шаг 3 нужен потому, что токен мог утечь по дороге. Связка «токен + свой
Telegram» означает, что подобранная или подсмотренная ссылка одна ничего не
даёт.

## Роли

| Может | владелец | читатель |
| --- | --- | --- |
| смотреть ленту, поиск, правки, сущности, досье | да | да |
| свои темы, свои запросы, своя отдача в бот | да | да |
| менять источники, интервалы, включать и выключать сбор | да | нет |
| чистка копий, сжатие базы, диагностика | да | нет |
| «Опросить сейчас», кнопки модели | да | нет |
| выдавать и отзывать приглашения | да | нет |

Проверка роли — в одном месте, в `web.route`, до вызова страницы: список
путей, требующих владельца. Не в шаблонах: спрятанная кнопка не защищает.

## Отзыв

Страница «Доступы»: кто приглашён, когда вошёл в последний раз, откуда.
Кнопка «отозвать» ставит `отозван_в`, гасит все сессии этого человека и его
темы перестают слать. Плюс рубильник «выйти везде» — очистка `sessions`
целиком; он же нужен при подозрении на утечку.

## Защита самого приглашения

- 256 бит случайности: подбор бессмыслен.
- Ограничение попыток: пять неверных кодов с одного адреса — пауза, дальше
  растущая задержка. Ведро в памяти процесса, как `bridge`.
- Ответ одинаковый для «нет такого», «просрочено» и «уже использовано»:
  разные ответы рассказывают подбирающему, что он угадал форму.
- Токен не пишется в журнал никогда: маскирование как у токена Telegram.
- Ссылка одноразовая, срок по умолчанию 72 часа.

## Подводные камни выхода в открытый интернет

**Прокси и адреса.** Сервер слушает `127.0.0.1`, снаружи Caddy. Значит
`X-Forwarded-For` можно доверять только от него, иначе ограничитель попыток
обманывается одной строкой заголовка. Правило: если запрос пришёл не с
локального адреса — заголовок игнорируем.

**Свой разбор HTTP.** Он маленький и это его достоинство, но между Caddy и
нами появляется классическая щель: запрос с одновременными `Content-Length`
и `Transfer-Encoding` два разных разборщика понимают по-разному. Такие
запросы надо отвергать явно. Заодно — потолок на длину заголовков и на число
одновременных соединений: у нас одно ядро, и десяток медленных запросов уже
отказ в обслуживании.

**Куки.** На публичном домене `Secure` обязателен, а не по переменной.
Префикс `__Host-` запрещает подмену куки с соседнего поддомена. К метке
формы стоит добавить проверку `Origin` и `Sec-Fetch-Site`.

**Заголовки.** JavaScript у нас нет вовсе, поэтому политика может быть
почти запретительной: `default-src 'none'`, стили только свои,
`form-action 'self'`, `frame-ancestors 'none'`, `base-uri 'none'`. Плюс
`X-Robots-Tag: noindex` на всё: архив снятых материалов в поиске Google —
это разговор с юристами издания, а не техническая задача.

**Чужой контент.** `/копия` отдаёт сохранённую чужую страницу. Внутри —
законно как доказательство, наружу — публикация чужого материала, в том
числе снятого. Эта страница должна быть доступна только владельцу и
отдаваться вложением, а не для просмотра.

**Персональные данные.** Сущности «человек» — это данные о людях, собранные
и хранимые. Появляются просьбы удалить; нужна возможность удалить сущность
и её упоминания, не ломая архив.

**Сбор с публичного адреса.** Когда машина светится наружу, издания видят и
её; блокировка по адресу ударит по сбору. Интервалы, откаты и честный
`User-Agent` уже есть — их нельзя терять ради скорости.

**Секреты и следы.** Токен бота и ключ модели — в `EnvironmentFile` с
правами `600`. Резервные копии базы содержат всё, включая копии страниц:
шифровать. В диагностических журналах окружение маскируется — это надо
проверять при каждом новом ключе.

**Деньги.** Кнопки модели тратят бюджет. Для роли «читатель» они закрыты, но
и владельцу стоит оставить потолок вызовов в сутки: утечка сессии не должна
превращаться в счёт.

**Оповещение.** Каждый успешный вход и каждое использованное приглашение —
сообщение владельцу в бот: «вошла Марина, адрес такой-то». Это дешевле любой
системы обнаружения вторжений и работает сразу.

## Порядок работ

1. Таблица `invites`, роль в `users`, команда бота `/пригласить`, страница
   активации, привязка к Telegram.
2. Проверка роли в `web.route` и закрытие владельческих путей.
3. Ограничитель попыток, одинаковые ответы, маскирование токена в журнале.
4. Страница «Доступы»: список, отзыв, «выйти везде», оповещения в бот.
5. Заголовки безопасности, `Secure` по умолчанию, отказ от двусмысленных
   запросов, доверие `X-Forwarded-For` только от прокси.
