# Шаг 9. OSINT-слой: поиск, материал, сюжет

Шаг закрывает этапы 1–2 из `docs/news-osint.md`: полнотекстовый поиск по архиву с фильтрами, страница материала с историей правок и страница сюжета. Диффы правок, сущности, граф связей и всплески остаются на следующие шаги.

Ограничения площадки: одно ядро, 500 МБ памяти, без JavaScript. Тяжёлые выборки — только по запросу и с потолком строк [CORE-025]. Наблюдение и машинная оценка разделены [NEWS-008]. В каждой строке выдачи — ссылка на оригинал [NEWS-007]. Отсутствие данных не равно нулю [NEWS-001]. Модели в горячем пути поиска нет [NEWS-002]: ранжирование даёт bm25, не эмбеддинги.

Состояние на 25.09.2026: этапы 1–3 написаны — `news/search.py`, `news/pages.py`, `news/web.py`, тесты `tests/test_news_search.py` и `tests/test_news_web.py`. Тесты прогнаны: `pytest -q` по `tests/test_news_*.py` — 103 passed, `pyflakes news tests diag.py` — чисто. Прогон вскрыл ошибку: псевдоним `items_fts f` в запросах (`f MATCH ?`, `bm25(f, ...)`) на SQLite 3.40 даёт «no such column: f» — 11 тестов падали; в запросах оставлено полное имя таблицы. Замеров размера индекса и времени запроса на реальной базе по-прежнему нет [DOC-005].

## 1. Поисковый индекс

Виртуальная таблица FTS5 поверх `items` во внешнем содержимом, чтобы не дублировать тексты (константа `INDEX_SQL` в `news/search.py`):

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS items_fts USING fts5(
  title, lead, body,
  content='items', content_rowid='id',
  tokenize="unicode61 remove_diacritics 2"
);

CREATE TRIGGER IF NOT EXISTS items_fts_ai AFTER INSERT ON items BEGIN
  INSERT INTO items_fts(rowid, title, lead, body)
  VALUES (new.id, new.title, new.lead, new.body);
END;

CREATE TRIGGER IF NOT EXISTS items_fts_ad AFTER DELETE ON items BEGIN
  INSERT INTO items_fts(items_fts, rowid, title, lead, body)
  VALUES ('delete', old.id, old.title, old.lead, old.body);
END;

CREATE TRIGGER IF NOT EXISTS items_fts_au AFTER UPDATE OF title, lead, body ON items BEGIN
  INSERT INTO items_fts(items_fts, rowid, title, lead, body)
  VALUES ('delete', old.id, old.title, old.lead, old.body);
  INSERT INTO items_fts(rowid, title, lead, body)
  VALUES (new.id, new.title, new.lead, new.body);
END;
```

Первичное заполнение существующей базы — один раз при создании индекса:

```sql
INSERT INTO items_fts(items_fts) VALUES('rebuild');
```

Триггер обновления ограничен колонками `title, lead, body`: правки служебных полей (`sent_at`, счётчики проверок) индекс не трогают.

Это делает `ensure_index(conn)`: читает `sqlite_master`, и если таблица и все три триггера на месте — выходит сразу, без записи и без `commit`. Старый триггер `items_fts_au` без `UPDATE OF` пересоздаётся. При отсутствии индекса создаёт таблицу с триггерами и один раз перестраивает. Вызов идёт рядом с инициализацией схемы (`store.ensure`, `LATE_COLUMNS`).

Запас по памяти: индекс примерно равен 60–80 % объёма текстов, ориентир из `docs/news-osint.md` — около 3 МБ в день. Раз в сутки в обслуживании вызываем `optimize(conn)` (`INSERT INTO items_fts(items_fts) VALUES('optimize');`).

## 2. API поиска

Модуль `news/search.py` — отдельный файл, а не рост `store.py` [CODE-003]. Имена функций английские, ключи словарей русские — как в `store.py`.

```python
def search(
    conn,
    query: str,
    *,
    source: str | None = None,
    since: str | None = None,
    until: str | None = None,
    topic_id: int | None = None,
    only_original: bool = False,
    only_revised: bool = False,
    limit: int = 50,
    offset: int = 0,
) -> list[dict]
```

- Запрос уходит в `items_fts MATCH ?`, ранжирование `ORDER BY bm25(items_fts, 4.0, 2.0, 1.0), COALESCE(published_at, listed_at) DESC` — заголовок весит больше тела, время публикации подстраховано временем обнаружения [NEWS-001].
- `only_original` — `dup_of IS NULL`; `only_revised` — `EXISTS (SELECT 1 FROM item_revisions r WHERE r.item_id = items.id)`.
- Даты сравниваем через `date(...)`, формат ISO; `since`/`until` включительно.
- `topic_id` разворачивается в коды источников темы; если тема пуста или не найдена — выдача пустая, а не «все подряд».
- Лимит ограничен сверху `MAX_LIMIT = 200`, сдвиг постраничный.
- Пользовательский ввод проходит через `prepare(query)`: спецсимволы FTS5 вырезаются, слова оборачиваются в кавычки, со `PREFIX_FROM = 4` символов добавляется префиксная звёздочка. Пустой результат подготовки = поиск не выполняется.

Дополнительно:

```python
def item(conn, id: int) -> dict | None    # материал + правки + сюжет
def story(conn, id: int) -> dict | None   # участники сюжета по времени
```

`story` берёт корень сюжета (`dup_of` или сам `id`), считает: кто опубликовал первым, лид-тайм каждого последующего издания относительно первого, кто попал в сюжет как повтор. Меньше двух участников — `None`.

## 3. Маршруты

В `news/web.py` и функции разметки в `news/pages.py` (чистые функции, `html.escape` на всём пользовательском):

| Маршрут | Назначение |
| --- | --- |
| `GET /поиск` | форма и выдача: `?q=`, `?источник=`, `?с=`, `?по=`, `?тема=`, `?оригиналы=1`, `?правки=1`, `?стр=` |
| `GET /материал?id=` | материал: заголовок, лид, источник, время публикации и обнаружения, ссылка на оригинал, история ревизий, сюжет |
| `GET /сюжет?id=` | сюжет: кто первым, лид-тайм остальных, список публикаций по времени |

Параметры запроса русские (как остальные маршруты), в `search` они переводятся в английские аргументы. Обе страницы по идентификатору отвечают 404 с внятной фразой, если материала или сюжета нет.

Правила выдачи: в каждой строке — издание, время публикации и ссылка на оригинал; пустой результат — явная надпись «ничего не найдено» с оговоркой, что это не доказательство отсутствия события [NEWS-001]; постраничность по `pages.PER_PAGE = 50` строк, «дальше»/«назад» обычными ссылками; чужое тело статьи не показывается ни в выдаче, ни в карточке — только заголовок, лид и ссылка [NEWS-007].

Страница материала показывает историю правок как перечень «когда — новый заголовок — длина»: текстов ревизий мы пока не храним, диффы откладываем на следующий шаг и отмечаем это на странице.

## 4. Тесты

В `tests/test_news_search.py` и `tests/test_news_web.py` (прогнаны, 103 passed):

- индекс строится на пустой и на заполненной базе (`rebuild` не ломает существующие данные);
- триггеры: вставка, изменение и удаление материала меняют выдачу поиска;
- фильтры: источник, диапазон дат, только оригиналы, только с правками;
- ранжирование: совпадение в заголовке выше совпадения в теле;
- экранирование: запрос с кавычками и звёздочкой не роняет поиск;
- лимит и сдвиг: потолок строк соблюдается;
- веб: `/поиск` без запроса ничего не ищет, с запросом даёт ссылку на оригинал и на карточку, пустая выдача поясняется словами, страницы второй и первой страницы резаны по 50;
- веб: `/материал` показывает лид и ссылку, но не тело чужой статьи; несуществующий и нечисловой `id` — 404;
- веб: `/сюжет` называет первое издание и отставание остальных, одиночный материал даёт 404;
- веб: все три страницы требуют сессии и экранируют HTML в заголовках;
- триггер обновления: правка `sent_at` и счётчиков проверок не пишет в индекс (`conn.total_changes`);
- `ensure_index` пересоздаёт старый триггер `items_fts_au` без `UPDATE OF`;
- поиск с фильтром по теме (`topic_id`).

## 6. Риски

- Рост базы: индекс удваивает вес текстов. Решение — `optimize` и обсуждаемое хранение текстов год.
- Тяжёлый запрос на одном ядре: спасают лимит строк, постраничность и отсутствие поиска без непустого запроса.
- Морфология: FTS5 ищет по словоформам. Стеммер русского не подключаем, вместо этого включён префиксный поиск от 4 символов.
- Этапы 1–3 проверены только тестами; поведение на реальной базе (объём индекса, время запроса) не измерено [DOC-005].
